# AFTER HOURS — THE LITTLE CLUB
## AFTER CL TO MOON 홈페이지 통합 개발 핸드오프
**버전:** 2026-11-16 / 최종 결정 반영  
**목표:** 기존 Next.js 홈페이지 안에 유효한 회원권 보유자만 접근할 수 있는 작은 픽셀아트 클럽을 붙인다.  
**참고 소스:** `demo/index.html`(기존 독립 실행형 데모), `AFTER_HOURS_LITTLE_CLUB_CONCEPT.gif`(연출 참고), `references/*`(사용자 제공 사진에서 파생한 참고 파일).

> 중요: GIF는 연출 참고이지 실제 구현 화면/실측 도면이 아니다. HTML은 데모이지 운영 서버와 연결된 완성본이 아니다. 구현 완료 여부는 실제 홈페이지에서 검증한다.

### A. 작업 목표와 범위

1. 기존 AFTER CL TO MOON 웹사이트(`https://aftercltomoon.vercel.app/`)의 라우팅·회원권·인증·권한·Neon DB 구조를 **먼저 확인**한다. 기존 코드에서 재사용 가능한 컴포넌트와 정본 데이터를 우선한다.
2. 신규 보호된 게임 페이지(권장 경로 `/little-club`, 실제 라우트 충돌 시 조정)를 기존 회원용 내비게이션에 통합한다.
3. 실내 공간(워크아웃, 볼더링, 테이블, 라운지)과 실외 가상 모닥불 캠핑 장면을 오갈 수 있다.
4. 달토끼 캐릭터 16가지 MBTI별로 구별되는 **행동 모션**을 부여한다. 모두 다른 동물로 바꾸지 않는다.
5. 최초 입장 때 별명·MBTI를 선택하고 저장한다. 회원은 이후 프로필/게임 설정에서 언제든 변경할 수 있다. 실제 게임 안에는 **`별명 · MBTI` 동시 표기**가 원칙이다.
6. 짧은 **현재 상태 말풍선**은 **실내와 실외 모두**에서 띄운다. 채팅 시스템·과거 대화 내역은 만들지 않는다.
7. 볼더링 벽을 누르면 **기존 MOON PROBLEMS** 데이터에 기반한 문제 목록/상세를 연다.
8. 기존 **AFTER HOURS RADIO**를 동일 화면에서 재생·조작할 수 있다. 복제 구현 금지.
9. 본인 프로필에 기존 회원 정보와 **실제로 지급된 스탬프**를 표시한다.
10. 실제 클럽 사진을 바탕으로 실내 일반 모드/나이트 모드를 구성한다. 나이트 모드는 실제 조명 사진의 보라·파랑·청록 천장 프로젝션을 참고한다.
11. 두 강아지(갈색·흰색 장모견 / 검정·흰색 단모견)를 실내/캠핑의 조연 캐릭터로 넣는다. 이름표·MBTI 부여하지 않는다.
12. 한글 빈티지 간판 **`매달려야 산다`**를 라운지 상단 벽면 또는 입구 인근에 자연스럽게 배치한다. 이 문구는 공식 로고가 아니며, 문구를 바꾸지 않는다.

**제외:** 별도 게임 서버, WebSocket 기반 대규모 동시 접속, 실제 클라이밍 기록 자동 저장, 게임 보상으로 회원 스탬프 자동 지급, 채팅 기록/DM/댓글, 새 라디오 백엔드, 신규 결제/회원권 체계, 개발과 관계없는 기능 확장.

### B. 확정된 실내 공간 관계 — 사용자 진술 우선

| 위치 | 반드시 표현할 것 |
|---|---|
| **왼쪽** | 워크아웃: 덤벨, 박스, 줄넘기, 밴드 |
| **오른쪽** | 주 볼더링 암장: 합판 벽체, 다양한 홀드·볼륨, 블루/그레이 매트 |
| **암장 앞쪽** | 낮은 테이블 |
| **암장 뒤쪽** | 라운지(소파·레코드·휴식) |
| **라운지/입구 벽** | 레트로 조명 간판 `매달려야 산다` |
| **실외** | 실제 암장 구조와 혼동되지 않는 *가상* 작은 캠프파이어 장면 |

- **사용자 진술과 실제 제공 사진이 기존 데모/GIF 배치보다 우선**한다.
- `references/concept_floorplan_not_asbuilt.jpg`는 과거 **콘셉트 렌더링**으로 실측 자료가 아니다.
- `references/lounge_construction_photo.jpg`는 **공사 중 사진**이므로 완성 배치라고 가정하지 않는다.
- `references/night_mode_actual_wall.jpg`는 암장의 **실제 나이트 조명 참고**이며 천장 배관·벽체·홀드의 물리적 관계를 임의 변경하지 않는다.
- 픽셀아트는 단순화 가능하나 좌우 구역 및 앞뒤 관계를 바꾸지 않는다. 실제 구조·치수는 확인되지 않은 부분을 추정하지 않는다.
- 공식 로고는 반드시 **사이트의 승인된 원본 에셋**을 사용한다. `AFTER / CL TO(브러시 가로 취소선) / MOON + 노란 초승달` 구성 유지. 생성형 이미지에 그려진 로고를 공식 원본으로 사용하지 않는다.

### C. 동작 및 UI

**접근**
- `applicant`, `inactive`, 만료·미등록·시작 전 회원권 등은 차단. `active` 계정이라도 실제 회원권 유효기간 확인.
- 서버에서 인증·인가 후 페이지를 렌더하고, 게임 데이터 API도 동일하게 보호한다. JS 변수와 localStorage만으로 접근 판정하지 않는다.
- 관리자/운영자도 별도 합의된 예외가 없다면 '유효 회원권 보유자' 조건을 따른다. 인증 불가 시 안내+기존 회원권 페이지로 돌아가기.

**캐릭터/프로필**
- 최초 진입: 별명(기존 프로필 값이 있으면 프리필) + MBTI(16개) 선택 후 게임 시작.
- 이후 `설정 / 내 프로필`에서 수정하고 Neon DB 정본에 저장해 재방문 시 유지.
- 실게임 이름표 `별명 · MBTI`; 길이 제한/HTML escape 및 무해한 입력 검증.
- **GIF에서는 이름표 없음**: 이것은 콘셉트 GIF에 한정된 연출 결정이며 게임 UI 요구사항을 덮어쓰지 않는다.
- 다른 실제 회원의 아바타를 표시한다면 해당 회원의 표시 동의 여부를 확인한다. 동의하지 않은 사람의 별명/MBTI/접속 여부를 노출하지 않는다. 비회원/미동의 시 가상 NPC로 대체하고, 실제 접속·재실 위치를 뜻하는 것처럼 보이지 않게 한다.
- MBTI 모션은 놀이를 위한 선택 가능한 표현이며 심리학적 성격 판정을 의미하지 않는다.

**모션**
- 16유형 모두 서로 다른 기본 대기 행동/소품/작은 제스처(실제 게임에서 한눈에 차이 확인). 예: 경로 살피기, 응원, 레코드 듣기, 덤벨 운동, 포스터 읽기, 담요에 앉기, 컵 들기, 흥얼거리기 등. '색만 다른 16마리' 금지.
- 강아지 둘: 사용자 사진 기반 외형(갈색·흰색 풍성한 털, 검정·흰색 짧은 털+뾰족 귀), 자연스러운 고개·꼬리·자세 변화. 픽셀아트 재해석; 사진 그대로 공개하지 않음.
- 애니메이션은 과도한 흔들림/바운싱이나 이미지 전체 줌이 아니라 피사체 동작 중심. `prefers-reduced-motion` 및 저사양 대응.

**상호작용**
- 실내: 볼더링, 워크아웃 배경, 소파에 앉기, 레코드 선택, 라디오 조작, 벽에서 문제 보기, 실외 이동.
- 실외: 모닥불에 앉기, 잠깐 쉬기, 실내 복귀, 현재 상태 말풍선.
- 말풍선: **실내·실외 모두** 짧게 입력/표시하며 '지금 하는 일/기분' 수준. **현재 한 건만 유지**하고 히스토리·채팅 UI 없음. 본인 표시만으로 시작할 수 있으며 타 회원에 노출한다면 선택적 공개와 만료(예: 30분), 최신값만 upsert, 무한 폴링 금지. 정책이 불확실하면 외부 공개 범위를 확장하지 않는다.
- **문제:** 우측 볼더링 벽 hitbox를 누르면 `/problems`의 실데이터를 조회한 팝오버/패널 또는 기존 상세 페이지로 이동. 출제자 노트·체감 난이도·평가·완등/후기 등은 기존 권한과 데이터 형식 그대로. 사진/벽 위치/문제 ID 연결이 없다면 가상의 ID나 점수/홀드 경로를 만들지 말고 기존 문제 목록으로 연결. 게임 속 홀드 루트는 **데모**로만 별도 표시하고 실제 문제로 오인되지 않게 한다.
- **라디오:** 기존 `/radio` 로직/플레이어를 재사용한다. 실내↔실외 전환 시 플레이어가 재마운트되지 않게 상위 공통 레이아웃에 유지. 실제 YouTube 재생, 브라우저 autoplay 정책, 임베드 CSP/X-Frame-Options 조건을 검증. 불가능 시 원본 라디오 페이지를 별도 링크로 연다. 가짜 음악 재생 상태를 표시하지 않는다.
- **스탬프:** `/me` 및 기존 스탬프 정본 연동, 본인 승인/획득 기록만 서버에서 조회. 6+1, 12+2 등 이미 운영 중인 스탬프 정책을 참조하되 운영자 승인 로직 우회하지 않는다. 게임 내 클라이밍 성공 ≠ 스탬프 획득.

### D. 데이터·라우팅 제안 (실제 코드 확인 후 조정)

| 화면/기능 | 구현 원칙 |
|---|---|
| `/little-club` | 기존 인증·회원권 서버 보호를 받는 신규 페이지(경로는 예시) |
| `/me` | 기존 프로필/획득 스탬프 원천 재사용 |
| `/problems`, `/problems/[id]` | 기존 운영진 출제 문제 및 회원 피드백 화면 재사용 |
| `/radio` | 기존 신청곡·재생 로직 재사용 |
| Profile fields | 기존 nickname/MBTI 데이터 있으면 재사용; 없을 때만 최소 필드 추가 |
| Current bubble | 히스토리 테이블을 만들지 말고 일회성 클라이언트 상태 또는 회원별 단일 최신 상태만 저장 |
| 네트워크 | 실시간 채팅·별도 DB·웹소켓 불필요. 목록/상태 조회는 탭 비활성 시 중단 |

계정 상태(`applicant`/`active`/`inactive`)와 회원권 유효성의 실제 테이블·컬럼명을 **기존 소스에서 확인**한다. 이름만 보고 구현하지 않는다. DB 변경 전 마이그레이션 계획과 롤백을 마련한다. 민감한 토큰/DB 접속 정보는 클라이언트에 넣지 않는다. 기존 접근 제어 정책을 재사용한다.

### G. 테스트 및 승인 기준

**P0 / 배포 차단:** 만료·미등록 계정 접근 실패(직접 URL·API 포함), 유효 회원권 접근 성공, 계정 간 프로필/스탬프 교차 조회 차단, 별명/MBTI 최초 저장 및 수정 후 유지, 실내·실외 말풍선, 기존 실제 `/problems` 호출(가상 ID/평점 없음), 기존 `/radio` 재생, 타 회원 정보 사전 동의 없이는 미노출.

**P1 / 시각 품질:** 왼쪽 워크아웃/오른쪽 볼더링/암장 앞 테이블/암장 뒤 라운지, 실제 야간 조명 색감, 공식 로고 원본, `매달려야 산다` 정확 표기, 두 강아지 형태, MBTI 16종 구분 가능한 자연스러운 모션.

**P1 / 서비스 품질:** 390px 모바일 폭 가로 스크롤 없음, 탭 비활성화 시 렌더링 중지, 모션 축소, 장면 이동 중 라디오 지속(가능한 브라우저에서), 이미지/요청 부하 확인, 실제 스마트폰 재생·터치 확인.

**완료 보고 형식:** 구현 경로/커밋, 서버 접근 제어 근거, 실제 화면 캡처·모바일 테스트, DB 마이그레이션 여부, `PASS / FAIL / NOT VERIFIED` 테스트 표. 완료로 선언하기 전에 각각 확인한다. `DONE ≠ VERIFIED`.

### H. 개발 순서

1. 실제 레포 분석(인증/회원권/Neon 스키마/`/radio`/`/problems`/`/me`/공식 로고 경로).
2. 신규 보호 라우트 및 게임 컴포넌트 분리 — 데모 HTML을 무작정 통째로 붙이지 말고 Next.js `use client` 구성과 접근 제어 분리.
3. 실제 공간 구조로 픽셀아트 배경 교체 + 나이트 모드 + 간판·반려견.
4. 최초 별명·MBTI 선택/수정 저장, 회원 프로필·스탬프 조회.
5. 벽 클릭 → MOON PROBLEMS, 공통 라디오 플레이어 연동.
6. 실내/실외 현재 말풍선, 모바일/접근성/부하 검수.
7. 기능별 완료·미검증 항목을 구분해 보고. 기존 화면 기능을 삭제하거나 대체하지 않는다.

**운영비:** 기존 Vercel + Neon 인프라 안에서 우선 구현한다. 새 유료 서비스·실시간 서버·무한 폴링 추가 금지. 실제 무료 요금제 사용 적합성·한도는 사이트의 용도 및 현행 약관을 개발자가 확인할 것.
