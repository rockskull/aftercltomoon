# Claude Code에 그대로 붙여넣는 최종 개발 지시문

첨부된 `AFTER_HOURS_LITTLE_CLUB_FINAL_HANDOFF_20261116.zip`을 풀고 `README_FIRST.md` → `CLAUDE_HANDOFF.md` → `INTEGRATION_MATRIX.md` → `ASSET_MANIFEST.md` → `TEST_AND_RELEASE.md` 순으로 읽으세요. `CLAUDE_HANDOFF.md`가 **정본 요구사항**입니다.

대상은 기존 AFTER CL TO MOON Next.js App Router / Vercel / Neon DB 레포입니다. 새 프로젝트/DB/라디오 엔진을 만들지 말고 **현재 레포 안에서 증분 통합**하세요. 데모 `demo/index.html`은 플레이 감각과 UI 동작을 참고하는 독립형 프로토타입이지, 서버 인증이 검증된 프로덕션 코드가 아닙니다. HTML을 통째로 `dangerouslySetInnerHTML` 또는 공개 정적 파일로 배포하지 마세요.

**먼저 읽기 전용 조사 결과를 제출**하세요: 기존 라우트·인증 미들웨어/서버 접근 제어·유효 회원권 판정 방식·계정 상태(`applicant`, `active`, `inactive`)·Neon 스키마·`/radio` 플레이어·`/problems` 실제 데이터·`/me` 및 공식 스탬프·공식 로고 에셋·현재 미디어 저장 경로. 확인한 코드 경로와 근거를 적고, 재사용/추가/수정 파일 목록·DB 변경 필요 여부·회귀 위험을 계획하세요. 미확인 DB 컬럼이나 API를 추정하지 마세요.

**구현 범위**
1. 기존 인증 아래 보호된 `/little-club` (충돌 시 실제 경로를 보고). 보호 페이지뿐 아니라 모든 게임 관련 API도 서버 회원권 확인. 만료/미등록/시작 전/비활성 사용자는 차단. 관리자 우회는 별도 합의 없이는 금지.
2. 공간을 **왼쪽 워크아웃(덤벨·박스·줄넘기·밴드) / 오른쪽 볼더링 / 암장 앞 낮은 테이블 / 암장 뒤 라운지** 관계로 수정. 사용자 제공 실제 사진 우선, 과거 콘셉트 평면과 GIF를 실측으로 간주하지 않음. 실제 나이트 조명의 보라·파랑·청록 느낌 표현. 실외는 가상 모닥불 캠핑까지.
3. MBTI 16유형 모두 **달토끼**를 유지하고 각기 구분되는 행동 모션 구현. 최초 별명·MBTI 선택 후 Neon DB에 최소 필드로 저장, 재방문 유지/수정. **실제 게임에는 `별명 · MBTI` 이름표**; GIF 이름표 없음 결정은 GIF 한정.
4. 실내·실외 현재 상태 말풍선 각 1건 표시/수정. 채팅·대화 이력/DM/타 사용자 현재 위치 기능 금지. 타 회원 정보는 명시적 동의 없이 노출 금지.
5. 오른쪽 볼더링 벽 상호작용 → 기존 `/problems` 데이터 화면/상세. 가상 문제 ID, 점수, 홀드 루트를 실데이터처럼 표현 금지. 실제 벽 위치 매핑 데이터가 없다면 목록/기존 상세로 연결.
6. 레코드 상호작용 → **기존** `/radio` 플레이어 재사용. 게임 내 재생 지속 가능성을 살피되 브라우저/임베드 제약을 검사하고 불가 시 원본 페이지 링크로 안전하게 폴백. 가짜 재생 상태 금지.
7. `/me`에서 이미 획득한 **실제 스탬프만 조회**. 게임 내 등반/휴식으로 스탬프 지급 금지.
8. 실제 사진 기반 강아지 2마리(갈색·흰색 장모견, 검정·흰색 단모견), 공식 로고 승인 원본, 간판 정확 문구 `매달려야 산다` 구현. 원본 없는 경우 임의 재생성하지 말고 **에셋 필요**로 표시.
9. 데스크톱 키보드와 모바일 터치, 모달 포커스·오버레이, `prefers-reduced-motion`, 가로 스크롤, 페이지 비활성 렌더링 중단을 점검.

**개발하지 않을 것**: 새로운 유료 인프라/게임 서버/실시간 멀티플레이 WebSocket/채팅·대화 이력/결제·회원권 재구현/새 라디오 백엔드/가상 공식 스탬프/운영과 무관한 기능 확장.

**작업·검증 절차**: 레포 조사 → 범위/수정파일/마이그레이션 필요성 보고 → 최소 기능 구현 → 실제 사용자 권한 매트릭스 테스트 → 기존 기능 회귀 테스트 → 모바일 및 미디어/모션 테스트 → 결과 보고. 저장소의 기존 작업을 덮어쓰거나 삭제하지 말고 변경 내역을 명시하세요. DB 변경 시 마이그레이션과 롤백을 준비하세요.

**최종 보고 형식**: 변경 파일/커밋, 구현 기능, DB 변경, 미구현/미검증, P0/P1 각 테스트 `PASS / FAIL / NOT VERIFIED`, 테스트 근거(명령/스크린샷/로그), 실배포 URL. 단순 빌드 성공으로 완료 처리하지 마세요. `DONE ≠ VERIFIED`.

**첨부 참고자료 주의**: 이 패키지에는 데모 HTML과 문서는 있지만 원본 사진·콘셉트 GIF는 포함되지 않습니다. `ASSET_MANIFEST.md`를 확인해 기존 자료를 확보하고 진행하세요. 원본을 찾을 수 없다면 누락 자산을 명시한 채 로직 구현을 우선하되 시각 완성·승인은 보류하세요.
