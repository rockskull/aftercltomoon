# 변경 B. AFTER HOURS — The Living Club
## Little Club에 추가하는 첫 번째 플레이 확장 / MVP 01

**기획 가설:** 회원이 가상 아지트에서 실제 클라이밍 문제를 발견하고, 그 문제를 현실에서 도전해 보고 싶어지는가?

**정체성:** 독립 게임이 아니라 **기존 AFTER HOURS — The Little Club 안의 ‘문제 발견’ 기능 확장**. 새로운 게임 명칭이나 회원 시스템으로 교체하지 않는다. 현실 벽/실제 문제 데이터를 보여주는 3~4분 탐색형 인터랙션. 실제 클라이밍의 자동 시뮬레이션은 하지 않는다.

## 1. 플레이 루프

```text
기존 Little Club 입장 (회원권 인증 · 4분 타이머 유지)
      ↓
기존 달토끼를 이동하여 오른쪽 볼더링 벽 탐색
      ↓
벽의 서로 다른 세 위치에서 공개 가능 문제 3개 발견 (0/3 → 3/3)
      ↓
문제 선택 → 실제 이름/난이도/출제자 노트/회원 반응 확인
      ↓
하나를 골라 기존 /problems/[id] 화면으로 이동
      ↓
기존 상세 페이지에서 완등·평가·후기 (게임이 대리 기록하지 않음)
      ↓
기존 세션 정책에 따라 아지트로 복귀 또는 여운 남기기
```

세 문제를 모두 **열람한 경우** 작은 발견 이벤트를 **한 세션에 한 번만** 노출한다. 제안 문구: `THE WALL REMEMBERS. DO YOU?` (**문구 확정 전, 설정 가능해야 함**). 점수·배지·스탬프·포인트·랭킹·추가 미션 없음.

## 2. UI / 조작

- 실내 배경과 기존 벽 클릭 기능을 유지하고, 오른쪽 실제 볼더링 벽 위에 **세 개의 눈에 띄되 과하지 않은 발견 지점**을 배치한다. 달토끼가 벽에 접근해야 선택 가능하도록 기존 조작을 재사용한다. 모바일은 터치 타깃을 충분히 확보한다.
- 세 개의 **실제 문제 자체**를 매핑하지만 실제 홀드 위치 정보가 없으면 특정 홀드나 완등 경로와 대응한다고 표현하지 않는다. 발견 지점은 **UI 핫스팟**임을 전제로 하고, 실제 문제 위치와 동일한 것처럼 연출하지 않는다.
- 발견 진척 `발견 0/3`을 화면에 소형으로 표시. 3문제 중 하나를 열람해야 카운트 상승(단순 hover/근접만으로 증가시키지 않음).
- 카드 정보: 실제 문제 이름, 기존 난이도(존재할 때), 공개 가능한 출제자 노트, 회원 반응(실제 기록이 있을 때). 값이 없는 필드는 '기록 없음'으로 처리하거나 표시 생략. 가상의 평균점수·완등률·문구·문제명·문제 ID 금지.
- 카드에는 `자세히 보기` → `/problems/[id]`가 연결되며, 반드시 실제 서버 권한 검사를 거친다. 반응/완등/후기는 **기존 상세 페이지**를 사용한다.
- 게임 속 3개 열람 완료 메시지는 **내 현재 세션에서만** 표시. 서버 저장·DB 쓰기 없음. 새 로그인/다음 회차에는 `발견 0/3`부터 다시 시작 가능.
- 3개 미만의 공개 가능한 문제가 있거나 지정 ID가 삭제된 경우 없는 것을 새로 만들어 채우지 말고 실제 남은 수/빈 상태를 안전하게 보여주며 운영자 설정을 확인하도록 한다.

## 3. 문제 지정 및 서버 데이터

- 현재 유효 회원이 볼 수 있는 문제 3개를 **운영자 지정**. MVP에서는 새 관리자 UI보다 **서버 측 구성 목록** 또는 기존 설정 데이터의 ID 3개 사용을 우선. 운영자가 문제 변경할 때 수정 지점을 문서화.
- 기존 MOON PROBLEMS(` /problems`, `/problems/[id]`)의 스키마와 공개 규칙이 **정본**. 페이지에서 렌더하는 권한과 API 응답 권한을 동일하게 맞추며, 숨김 베타·출제자 전용 노트·승인 전 문제·비공개 후기 등을 서버에서 걸러낸다.
- 권장 조회는 **게임 첫 벽 클릭 시 서버에서 3개 일괄 조회**, 적어도 매 30초 presence sync에 문제 조회가 섞이지 않도록 한다. 재접근 시 기존 응답을 게임 세션 안에서 재사용. 기존 사이트의 한정된 캐시/권한 정책 준수.
- 유효하지 않은 ID는 404 또는 비노출 처리, 클라이언트가 임의 ID를 보내 비공개 데이터를 조회할 수 없게 한다.
- DB 필드/테이블/ORM/실제 ID는 **기존 레포 확인 후 결정**. 예시 목업의 `BLUE ORBIT`, `LAST LIGHT`, `MOON WALK`, `V1~V3` 등은 **가상 자료이므로 운영 데이터에 절대 사용하지 않는다**.

## 4. 4분 제한 · **강퇴 때만 PNG** · 10분 쿨다운 (기존 기능 보존)

- 기존 Little Club의 **4분 이용 제한**을 이 플레이 때문에 늘리지 않고, 문서상 ‘3~4분’은 경험 설계 목표이지 추가 시간을 보장하는 조건이 아니다.
- **4분 제한에 도달해 시스템이 자동 강퇴할 때만** 기존 PNG 저장/표시(강퇴 화면의 스크린샷)를 실행한다. 일반 퇴장 직전에 PNG를 자동 생성하는 로직을 새로 넣지 않는다. 발견 카드를 강퇴 화면으로 대체하거나 강퇴 시 PNG 기능을 제거하지 않는다.
- **일반 나가기/문제 상세 이동/뒤로 가기/페이지 이탈/로그아웃은 자동 PNG 트리거가 아니다.** 기존 수동 스크린샷 버튼은 버튼을 직접 눌렀을 때만 작동하도록 유지한다.
- 기존 **10분 재입장 제한**은 상세 페이지 이동 등으로 우회되면 안 된다. `/problems/[id]` 이동 후 뒤로가기·재입장·브라우저 새 탭/새로고침 경로에서 기존 서버 측 세션 및 쿨다운 정책 유지.
- 현재 운영 코드에서 **상세로 이동하면 게임 세션이 종료되는지/단순 중단되는지** 먼저 확인. 이 결정에 따라 기존 타이머 흐름을 따르며 게임 상세 페이지용 별도 타이머/쿨다운 구현 금지. 사용자가 이탈 전에 ‘발견’ 진행을 유지할지 역시 이미 존재하는 세션 수명 내에만 복원(`sessionStorage`는 필요할 때만); 10분 제한을 우회하는 임시 저장 금지.
- 화면을 보고 있는 동안만 ON sync 유지. 4분 퇴장·상세 페이지 이동으로 게임을 벗어났다면 **타이머가 유령처럼 폴링하지 않도록** 한다.

## 5. 범위 외 (명시적 금지)

- 신규 게임 루트·게임 서버·WebSocket, 신규 채팅/DM/게시판, 다른 회원 실시간 이동 추적.
- 게임에서의 완등 판정·출석 보상·스탬프 자동 지급·경쟁/랭킹/가상화폐.
- 라디오 재구현, 문제 관리 플랫폼 신설, 기존 회원권/결제 재설계.
- 새로운 기능 때문에 Little Club의 기존 공간·MBTI별 달토끼 모션·라운지·캠핑·라디오·나이트모드·말풍선·이름표·스탬프를 제거/변경하지 않음.

## 6. 실제 검증 가설 (개발 이후)

3~5명의 회원에게 4분 내 플레이를 맡기고, (1) 세 문제의 존재를 스스로 발견했는지, (2) 문제 상세 화면을 열었는지, (3) 다음 실제 암장 방문에서 도전하고 싶은 문제가 생겼는지만 확인. 행동 증거 없이 ‘재미가 검증됐다’고 선언하지 않는다.


> **2026-11-19 최종 정정:** PNG 자동 저장·표시는 **4분 이용 시간 만료에 따른 시스템 자동 강퇴에서만** 수행. 자발적 퇴장, 문제 상세 페이지 이동, 일반 페이지 이탈에는 실행하지 않음. 기존 수동 스크린샷 버튼은 별도 유지.
