# 변경 A. 경량 접속·말풍선 동기화 (v6 → v7 규칙만)

## 1) 기존 v6에서 변경되는 것만

| 항목 | v6 (사용자 확인상 구현됨) | 새 기준 |
|---|---|---|
| 예상 이용 | 9명, 주 5회, 회당 4분 | **9명, 주 3회, 회당 4분** |
| 말풍선 + ON/OFF 조회 | 120초 간격 | **30초 간격** |
| presence 갱신 | 180초 간격 개별 heartbeat | **30초 단일 sync 요청에 합침** |
| OFF 만료 | 6분 | **최종 신호 후 75초** |
| 정상 종료 | 종료 신호(지원 여부에 따라) | **본인 탭 세션만 best-effort 종료** |

| 위치/애니메이션 | 클라이언트 로컬 | **변경 없음** |

## 2) 간단 API 계약 (기존 구조 우선)

권장 `POST /api/little-club/sync` 또는 기존 엔드포인트의 통합 처리:

- **입력:** 기존 로그인 쿠키, 현재 탭/기기별 임시 세션 식별자. 요청 본문 `memberId`만으로 권한 부여하지 말 것.
- **서버:** 유효 회원권 확인 → 본인 탭 `last_active_at=now()` 갱신 → 마지막 75초 내 활성 탭이 하나라도 있는 회원을 ON으로 판정 → 공개가 허용된 회원의 `nickname, mbti, statusText, isOnline` 스냅샷을 한 번에 반환.
- **상태 저장:** 기존 말풍선 마지막 1건만 저장하고 수정/삭제할 때만 변경. 회원권/공개 동의 필터 유지. 게임 위치/MBTI 동작은 서버 저장 없음.
- **부하:** 최초 진입 1회, 활성화된 전경 탭에서 매 30초 1회, 숨김/페이지 이탈/4분 만료/쿨다운 중 0회. 실내↔실외 전환도 타이머는 단 하나. 실패 시 백오프.
- **정상 종료:** 세션 단위 leave(`sendBeacon` 또는 `fetch keepalive`는 해당 사이트 인증·CSRF 정책을 확인하고 적용). 다른 활성 탭이 있으면 여전히 ON. 연결 끊김/프로세스 강제 종료는 75초 TTL 처리.
- **타 화면 지연:** 정상 이탈 시 관찰자 화면에 다음 30초 조회 후 OFF, 비정상 이탈 시 마지막 신호부터 75+30≈105초(정상 네트워크일 때). 이는 '정밀한 실시간' 보장이 아닌 근사 접속 상태임.

**중요:** 4분 자동 퇴장 처리에서 sync 타이머를 닫고 현재 탭 세션을 종료하도록 기존 타임아웃 종료 경로에 **연결**한다. 타이머를 별도로 생성하거나 게임 시간 종료 시 sync가 계속 반복되는 버그를 만들지 않는다.

## 3) 요청량 추정 (계획용, 요금 보장 아님)
- `9명 × 주 3회 × 52주/12개월 = 117세션/월`.
- 4분 사용, 30초 주기: 첫 진입 포함 약 8~9 요청/세션 → **936~1,053 통합 sync 요청/월**.
- 정상 종료 신호는 시도 기준 최대 117건/월. 말풍선/프로필 수정 저장은 별도, 발생량 미정.
- 문제 탐색 조회는 별개이며 게임 입장 시 또는 벽 최초 클릭 때 1회만 권고(최대 약 117회/월 + 문제 상세 조회/열람 빈도).
- **Neon CU-hours는 위 HTTP 요청 수만으로 계산할 수 없음.** 기존 사이트 전체 사용량과 DB 활성화/연결 관리를 배포 전후 실측.

## 4) 안전·소유권
- Next.js 서버 측 회원권 확인, 상태 수정은 본인 것만 허용. 다른 회원에게는 공개 동의된 `nickname, MBTI, status, ON/OFF`만 전달.
- 실시간 접속 시각·좌표·장면·행동·기기 정보를 다른 회원에게 노출하지 않음.
- 접속 상태 관리가 이미 구현되어 있으면 **최소 변경**. 2개 탭/기기 테스트는 필수.
