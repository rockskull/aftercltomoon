## 1. 확정 범위

**이용 권한:** 유효한 회원권을 가진 로그인 회원만 게임 페이지와 관련 API에 접근 가능. `active` 계정 상태만으로는 충분하지 않으며 회원권 기간을 서버에서 검증한다. 이 규칙은 관리자·운영자 예외 여부를 기존 정책에서 확인하고 임의 완화하지 않는다.

**장면:** 실제 공간을 참고한 (1) 실내 일반, (2) 실내 나이트, (3) 야외 가상 캠핑 모닥불. 캠핑은 다른 서비스나 별도 멀티플레이 룸이 아니라 같은 게임의 한 장면이다.

**물리 공간:** 왼쪽 워크아웃(덤벨·박스·줄넘기·밴드), 오른쪽 볼더링(합판·홀드·볼륨·블루/그레이 매트), 볼더링 **앞쪽** 낮은 테이블, 볼더링 **뒤쪽** 라운지(소파·레코드·휴식). 사진을 참고해 실제 구조 관계를 유지하되 없는 치수·배치를 추정하지 않는다.

**캐릭터:** 동일 종족의 달토끼. 16 MBTI마다 구별 가능한 **행동 모션**과 소품. 동작을 외형 색상만 바꿔 대체하지 않는다. 내 토끼만 브라우저에서 직접 조작. 다른 회원 토끼는 브라우저별 **안정적 랜덤 위치·자동 MBTI 모션**으로 표시하며 좌표/행동을 서버에 저장하거나 전송하지 않는다.

**프로필:** 별명과 MBTI 최초 선택·저장 및 이후 언제든 수정. 게임 본편에서는 토끼 머리 위 `별명 · MBTI · ON/OFF` 표시. MBTI는 캐릭터 콘셉트이며 실제 성격 진단으로 사용하지 않는다. 콘셉트 GIF에서는 의도적으로 이름표를 제거했으나 **게임 본편에서는 표시해야 한다**.

**말풍선:** 각 회원의 **현재 상태 문구 한 건만** Neon에 저장. 실내·실외 공통으로 표시하고 회원이 OFF/로그아웃해도 회원권·공개 동의가 유효한 동안 마지막 문구를 유지한다. 사용자가 직접 수정·삭제하기 전까지 자동 만료하지 않는다. 게임을 보고 있는 다른 회원에게 **30초 주기의 자동 동기화**로 새로고침 없이 반영한다. 채팅/히스토리/DM/댓글 기능은 만들지 않는다.

**ON/OFF:** 실제 위치나 클라이밍 활동이 아닌 **Little Club 게임 화면을 활성으로 보고 있는지에 대한 근사치**. 이름표 옆에 `ON` 또는 `OFF`만 노출하고 타인의 마지막 접속 시각·정확한 활동 기록·좌표는 노출하지 않는다. `ON` 화면 활성 신호는 **30초 주기의 말풍선 스냅샷 요청에 포함**한다. **마지막 신호 후 75초**를 넘기면 OFF. 정상 이탈은 세션 단위 종료 알림으로 즉시 OFF 처리 시도(수신자가 다음 동기화 시점에 반영), 비정상 이탈은 TTL로 안전하게 정리. 백그라운드일 때 신호/조회 중단. 다중 탭·기기가 있다면 어느 한 탭을 닫았다는 이유로 다른 활성 탭의 ON이 사라지면 안 된다.

**기존 기능 재사용:** 우측 암장 벽 탭 → 기존 `/problems`의 **MOON PROBLEMS** 실제 목록/상세. 기존 `/radio`의 **AFTER HOURS RADIO** 실제 플레이어를 게임 화면에서 재사용. 내 `/me`에 실제 운영자 승인/획득 스탬프 표시. 게임 내 가상 완등은 공식 스탬프로 기록하지 않는다. 실제 곡 재생은 사용자 제스처/YouTube 정책을 준수한다.

**분위기·브랜드:** 실내 일반/나이트 모드, 실제 야간 투사 조명의 청록·남색·보라 톤. 보내준 사진을 바탕으로 강아지 두 마리(갈색·흰색 장모견, 검정·흰색 단모견)를 동작하는 작은 조연으로 추가. 한글 빈티지 간판은 **`매달려야 산다`** 정확히 표기. 공식 AFTER CL TO MOON 로고는 사이트의 **승인된 원본**(AFTER / 가로선으로 지운 CL TO / MOON + 노란 초승달)을 재사용. AI GIF의 근사 로고를 공식 에셋으로 대체하지 않는다.

**개인정보:** 다른 회원 정보는 유효 회원권과 **프로필 공개 동의**를 확인한 뒤 별명·MBTI·현재 말풍선·ON/OFF만 전송. 동의하지 않은 회원은 실명/별명/성격정보 노출하지 않으며 일반 NPC로 대체 가능. 단순히 게임 입장을 했다는 사실만으로 타 회원에게 공개한다는 동의가 되지는 않는다.

## 2. v7 동기화 규칙 (이 절이 최종 기준)

| 상황 | 브라우저 → 서버 / 서버 → 브라우저 | 시점 |
|---|---|---|
| 게임 활성 진입 | 서버 회원권 검증, **동일 동기화 요청**에서 본인 세션 활성 등록 + 회원 말풍선·ON/OFF 스냅샷 응답 | 1회 즉시 |
| 게임 활성 유지 | **단일 요청**에서 본인 세션 신호 갱신 + 회원별 마지막 말풍선·ON/OFF 스냅샷 반환 | **30초마다 1회** |
| 별명·MBTI | 기존 회원 프로필 정본 변경 | 최초 설정/저장 버튼 시 |
| 현재 말풍선 | 본인 최신 상태 `UPSERT` 또는 삭제 | 저장/삭제 버튼 시 1회, 키 입력당 저장 금지 |
| 실내↔실외 / 라디오 조작 / 위치 이동 / MBTI 모션 | 서버 동기화 요청 추가 없음 | 모두 클라이언트 로컬 동작 |
| 게임 종료 / 게임 화면 숨김 | 해당 브라우저 세션만 best-effort 종료 알림, 반복 요청 중단 | `visibilitychange` / `pagehide` |
| 강제 종료·연결 끊김 | 마지막 활성 시각 기준 **75초 TTL**로 OFF 처리 | 서버 측 판단 |
| 다시 게임 전경 전환 | 30초 타이머 중복 생성 없이 즉시 동기화(동시 호출 debounce) | 탭 복귀 시 |
| 다른 사람의 말풍선 변경·삭제 | 다음 합쳐진 동기화 응답에서 자동 반영 | 활성 게임에서 대체로 **30초 이내** |
| 타 회원 ON/OFF 화면 반영 | 해당 세션 신호 변경 이후 다음 합쳐진 동기화에서 갱신 | 정상 종료 대체로 **30초 이내** / 비정상 종료 최대 약 **105초** |

**중요:** `30초`는 실시간 소켓의 보장 지연이 아니라 **정상 네트워크에서의 목표 주기**이다. 서버 장애·브라우저 일시 정지·숨김 탭에서는 지연될 수 있다. **비정상 종료 최대 약 105초**는 마지막 활성 신호 이후 **75초 TTL + 관찰하는 다른 브라우저의 최대 30초 조회 주기**를 더한 예측값이다.

**단일 동기화 요청:** 권장 `POST /api/little-club/sync`. 요청 시 현재 탭의 고유 `sessionId`를 바탕으로 본인 presence를 갱신하고, 응답에서 **한 번에 전체 공개 동의 회원들의 별명·MBTI·현재 말풍선·ON/OFF**를 받는다. POST 선택 이유는 읽기 + 본인 세션 갱신이 묶인 쓰기 요청이기 때문. **별도 30초 GET + 별도 heartbeat 요청 2개를 만들지 않는다.** 개발자는 기존 사이트 API 구성에 맞게 엔드포인트명을 조정할 수 있다. 세부 계약은 `SYNC_API_CONTRACT.md` 참조.

**다중 탭 처리:** 각 탭/기기는 서로 다른 임시 세션 ID를 사용한다. ON은 **기한 내 활성 상태의 세션이 하나라도 있으면 ON**이다. 종료 신호는 **자신의 세션만** 해제한다. 미수신 종료 이벤트는 TTL로 처리하며 별도 크론은 필요 없다. 현재 DB에 안전한 세션 구조가 없다면 최소 테이블(회원 ID·세션 ID·마지막 활성 시각)을 추가하고, 오래된 레코드는 게임 진입 시 등 저빈도 계기에만 지연 정리한다. 실제 DB 스키마 확인 전 마이그레이션을 강행하지 않는다.

**부하 관리:** 화면에 보일 때만 동기화 1개, 숨김/이탈 시 0개, 게임의 실내·실외 장면을 바꾸더라도 타이머 추가 생성 금지. 중복 요청 방지, 에러 시 재시도 간격 점진 증가(예: 30→60→120초), 성공 시 30초 복귀. 서버 쿼리는 필요한 필드만 선택, 인증/회원권 검사 중복 최소화, 기존 Neon 연결 방식/풀링 사용, DB 연결 오래 붙잡지 않기. 별도 WebSocket/SSE 서버, Redis, 대기 작업, 실시간 좌표/모션 저장 금지.

## 3. 확정된 월간 사용량 기준 및 추정

| 항목 | 최종 가정 및 계산 |
|---|---|
| 게임 사용자 | **9명** (전체 회원 수가 아니라 예상 실사용 회원) |
| 사용 빈도 | **주 3회 / 인당** |
| 세션 길이 | **4분** |
| 월간 게임 접속 | `9 × 3 × 52 / 12 ≈ 117회` |
| 전체 월간 플레이 시간 | `117 × 4분 = 468분 ≈ 7.8 플레이어-시간` |
| 통합 sync 요청 | 한 세션에 진입 포함 약 **8~9회**, 월 약 **936~1,053회** |
| 정상 이탈 알림 | 시도 기준 약 **117회/월**, 환경에 따라 미수신 가능 |
| 말풍선 수정·프로필 변경 | **예측 불가**. 저장할 때만 쓰기 |
| 위치·자동 모션 DB 요청 | **0회** |

이는 **HTTP 요청 추정**이지 SQL 쿼리 수·DB 사용 비용·Neon CU-hours 예측이 아니다. 동시 사용, 탭 숨김, 실패 재시도, 기존 홈페이지 트래픽에 따라 실제 값이 달라진다. **비교:** v6은 9명×주5회×4분(약 195회/월)·분리 요청·6분 OFF가 전제였으므로 그 요청 수와 직접 비교해 '항상 줄었다'고 주장하지 않는다. v7은 낮아진 이용 횟수와 빠른 ON/OFF 반영을 **한 번의 주기적 요청**으로 균형화한 설계다.

Neon의 2026-10 공식 발표 기준 Free는 프로젝트당 **1GB 저장소·월 100 CU-hours**이며 컴퓨트는 기본 설정에서 약 5분간 유휴 시 scale-to-zero한다. 서버 비용은 조회 건수보다 **컴퓨트가 활성인 시간·규모**의 영향을 받는다. 기존 홈페이지와 DB 할당량을 공유하므로 배포 전후 Neon CU-hours·Vercel 함수 호출량을 반드시 실측하라. 무료 사용을 **보장**한다고 쓰지 않는다. 참고: https://neon.com/blog/neon-free-plan-1-gb-per-project / https://neon.com/blog/new-usage-based-pricing

## 4. 데이터·통합 경계

| 대상 | 처리 지침 |
|---|---|
| `/little-club` | 기존 사이트 Next.js App Router 안의 회원권 보호된 페이지(경로 조정 가능) |
| `/me` | 기존 회원 프로필·실제 스탬프 원천 참조 |
| `/radio` | 기존 AFTER HOURS RADIO 재사용. 게임 장면 변경 시 플레이어가 불필요하게 재마운트되지 않게 구성 |
| `/problems` + `/problems/[id]` | 기존 운영진이 등록한 실제 문제·노트·평가 데이터를 권한대로 재사용 |
| 별명·MBTI | 기존 필드 확인 후 없을 때만 최소 확장; 유효성 검사·공개 동의 |
| 마지막 말풍선 | 회원별 **최신 1건**, 오프라인 유지, 삭제/동의 철회 반영, 과거 버전 저장 금지 |
| ON/OFF presence | **게임 화면 전경 세션**의 최근 활성 신호만 보관, 동기화 응답에는 bool만 반환. 정확한 접속 시각/세션 ID를 타 회원에게 공개하지 않음 |
| 타 회원 위치/모션 | 오직 브라우저 로컬 랜덤. 동기화 응답에 좌표/애니메이션 프레임 금지 |

**서버 보안:** 페이지뿐 아니라 모든 API 요청에서 실제 회원권/소유자 권한 검증. 미등록/기간 만료/비활성은 직접 URL/API 호출도 차단. 사용자 제공 `memberId` 값만 믿고 수정 허용 금지. JSON/HTML XSS 방지, 말풍선 길이 제한, 별명/MBTI 유효성 검사. 세션 ID는 탭별 임시 임의값으로 생성하고 서버 측 사용자와 매칭. 4분 체류 종료 후 DB에 계속 요청하는 타이머가 없어야 한다.

## 6. 현재 구현 수준 및 후속 작업

**이미 있는 것:** `demo/index.html`의 캐릭터 선택·MBTI 시각 모션·실내외 화면·라디오/프로필의 가상 UI, 콘셉트 GIF, 사진 참고 자료. **기존 홈페이지 운영 연동 여부는 확인되지 않았다.**

**개발자가 구현할 것:** 실제 공간에 맞는 맵·조명·간판·강아지, 서버 회원권 보호, nickname/MBTI 영구 저장/수정, 사진 기반 게임 아트, 실내외 말풍선 영구 저장·자동 동기화, 탭별 ON/OFF presence, 벽 클릭→실제 문제, 기존 라디오·스탬프 데이터 연결, 모바일/접근성/부하 테스트. HTML 데모가 실제로 연동되었다고 추정하지 않는다.

**개발 순서:** (1) 실제 레포/회원권/프로필/라디오/문제/스탬프/로고 소스 점검 → (2) 권한 보호 라우트 + 최소 DB 변경 설계 → (3) v7 sync 30초/TTL 75초 개발 + 2계정 다중 탭 테스트 → (4) 공간/캐릭터/나이트/라디오/벽/스탬프 실제 연결 → (5) 모바일·비공개 데이터·Neon 측정 → (6) 결과에 대해 `PASS / FAIL / NOT VERIFIED` 보고.

**완료 기준:** 사용자 요구 동작을 실제 회원 두 계정·모바일에서 검증하고, DB 마이그레이션/검증 결과 및 Neon CU-hours 관측 증빙을 제출한다. `DONE ≠ VERIFIED`.
