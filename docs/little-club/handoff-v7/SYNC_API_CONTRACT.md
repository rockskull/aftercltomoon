# v7 경량 동기화 — 구현 계약(권장안)

**목표:** 9명 × 주 3회 × 4분. 별도 실시간 게임 서버 없이 **30초에 1개 HTTP 요청**으로 서버 presence 갱신 + 말풍선/ON-OFF 일괄 조회. 실제 레포/DB 구조를 확인한 후 같은 계약을 지키는 범위에서 API 명칭과 저장 위치 조정 가능.

## API (개념 설계; 실제 코드/스키마 확인 전)

### `POST /api/little-club/sync`

요청: 인증된 세션 쿠키 + 현재 탭에서만 생성한 무작위 `sessionId` (HTTP body). `memberId`를 사용자가 임의 지정하지 못하게 서버의 로그인 정보에서 결정한다.

서버 처리 (인증·회원권 검증 먼저):
1. 현재 세션의 `last_active_at = now()`를 upsert (실제 DB·ORM에 맞춰 구현).
2. 현재 시각 기준 **최근 75초** 이내 활성 세션이 1개 이상인 회원만 `isOnline=true`.
3. 유효 회원권 + 프로필 공개 동의가 있는 회원에 한해 `memberId`, `nickname`, `mbti`, `statusText`, `isOnline`만 반환. **lastSeen, sessionId, IP, 위치, 모션/좌표 미반환**.
4. 초기 진입 및 30초 주기에 똑같은 응답 계약 재사용. 상태가 수정/삭제되면 다음 요청에서 최신값 확인.

예상 응답 형태(필드명은 참고):

```json
{
  "members": [
    {"memberId":"m1","nickname":"달밤","mbti":"INFP","statusText":"잠깐 쉬는 중","isOnline":true},
    {"memberId":"m2","nickname":"초승","mbti":"ESTP","statusText":null,"isOnline":false}
  ]
}
```

### `POST /api/little-club/presence/leave` (best effort)

- 현재 **자신의 `sessionId`만** 비활성/삭제한다. 브라우저 `visibilitychange`→hidden, `pagehide`에서 가능한 경우 `navigator.sendBeacon` 또는 `keepalive` 요청. 단, 크로스사이트 인증·CSRF 처리/요청 크기·클라이언트 정책 검증.
- 정상 종료 때 다른 브라우저는 **다음 sync (30초 이내)**에서 OFF. 종료 알림이 전달되지 않아도 TTL 75초 + 다른 화면의 최대 30초 대기(약 105초) 후 OFF.
- 두 탭/두 기기 중 하나가 종료되어도 나머지 활성 세션이 있으면 ON을 유지.

### `PATCH /api/little-club/status`

- 본인이 `저장` 또는 `삭제`를 눌렀을 때만 회원별 **마지막 말풍선 1개**를 갱신(`statusText: string | null`). 히스토리/로그 테이블 없음. 타인의 말풍선을 수정하는 API 금지.
- 외부 공유 동의·회원권 검증, 길이 제한, 공백/특수문자 안전 처리를 서버에서 검증. 저장 직후 내 UI 즉시 갱신. 다른 회원에게는 다음 sync 결과 반영.

### 프로필 (`/me` 또는 기존 회원 API 재사용)

- `nickname`, `mbti`, 표시 동의 설정을 최초 선택 및 명시적 수정 시만 저장. 매 30초 프로필을 갱신하지 않는다.

## Presence 저장: 최소 구현

- 기존에 세션 안전 presence 구조가 있으면 **재사용**. 없으면 최소 스키마: `(member_id, tab_session_id, last_active_at)`; `(member_id, tab_session_id)` 복합키, `last_active_at` 인덱스는 실제 조회 패턴에서 필요할 때만 결정.
- ON 판정은 `EXISTS(active session where last_active_at > NOW() - INTERVAL '75 seconds')`. 정상 leave는 해당 탭/기기 1행만 제거한다.
- 비정상 종료 행은 TTL 판단 시 온라인으로 취급하지 않는다. 스토리지 정리가 필요하면 게임 신규 입장 등 **저빈도 이벤트에서만** 지난 오래된 행을 batch 삭제하고 정기 크론을 만들지 않는다.
- 9명 소규모에서는 세션 수가 작고 말풍선 스냅샷도 작다. 복잡한 델타 API, WebSocket, Redis, 메시지 버스, 별도 푸시 서버 필요 없음.
- 장면 이동·라디오·토끼 위치/모션은 **서버로 호출하지 않는다**. 말풍선·접속 상태 응답을 받을 때마다 토끼를 새 좌표로 재배치하지 않는다.

## 클라이언트 주기와 안전장치

1. 페이지 로드·게임 활성/전경 전환 → 즉시 `sync`.
2. 활성일 때만 **30초마다 하나의 sync**. 실내/실외 컴포넌트마다 개별 타이머 금지. 하나의 최상위 게임 스코프가 타이머 소유.
3. hidden/pagehide 때 타이머 중단하고 best-effort `leave`. 복귀 시 세션 재사용 또는 새 세션으로 sync. 동일 요청 중첩 실행 방지.
4. 네트워크 실패 시 동일 시간대 다중 재시도 금지; 점진적 백오프(예 30→60→120초)로 호출 제한. 정상 응답 후 30초 복귀.
5. 실제 회원 프로필의 노출/회원권 유효성은 매 응답에서 다시 확인. 만료된 회원은 목록에서 제외되고 자신의 게임 API 접근도 차단.
6. 말풍선 수정 후 `sync`가 재렌더링을 발생시켜도 다른 토끼 위치/행동은 제자리에 유지. 성능 최적화를 위해 변경된 member 데이터만 갱신.

## 성능/비용 검증 (가정, 한도 보장 아님)

- 평균 월간 접속: `9 × 3 × 52/12 = 117회`.
- 회당 4분, 30초 sync: `t=0,30,60,90,120,150,180,210` 기준 **8회**, `t=240` 경계 요청까지 포함되면 **9회**.
- 월간 **936~1,053 sync 요청** + 종료 알림 최대 약 **117회** + 회원 본인의 말풍선/프로필 저장 이벤트. HTTP 요청 수이고 Neon SQL·CU-hours 숫자가 아니다.
- Neon 월간 CU-hours/데이터/프로젝트 기존 사용량을 배포 전후 점검. 마지막 이용 후 백그라운드 poll 누수 없는지 확인. scale-to-zero 조건·DB pooling 설정은 실제 Neon 프로젝트에서 검증.

## 금지·주의

- **비동의 회원 정보 공개 금지**, 요청자의 로그인 계정 아닌 멤버의 세션 갱신 금지.
- UI에 `ON`을 정확한 실시간 접속 보장 또는 실제 암장 재실로 해석하지 말 것.
- 접속 시각을 다른 회원에게 반환하거나 채팅/위치 기록을 쌓지 말 것.
- 인증 쿠키/권한 문제가 있는 `sendBeacon` 은 기능 검증 없이 강제 적용하지 말 것. 실패해도 **75초 TTL이 최종 안전장치**다.
